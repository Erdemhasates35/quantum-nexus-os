# Quantum Nexus Trading Data Foundation

Date: 2026-11-24

## Database

Supabase project `tglfvmwhrpelbxfvofca` is active on PostgreSQL 17.11 in ap-northeast-1. The trading system is isolated in the server-only `nexus_private` schema. The existing `public` schema remains the separate application domain; its existing legal/workflow tables were not rewritten.

The `nexus_private` schema now contains 39 tables:
- 6 original telemetry/execution-foundation tables
- strategy catalog and immutable strategy versions
- risk profiles and risk decisions
- venue account references and instrument metadata
- funding, OHLCV, order-book, order-flow and correlation observations
- idempotent order intents, exchange order events and fills
- position/balance snapshots and an asset-denominated PnL ledger
- reconciliation runs and discrepancy records
- agent profiles, leased task queue and worker heartbeats
- alpha observations and discovery hypotheses
- strategy allocations, venue health, cost metrics and circuit breakers
- execution routes, model registry, inference events, backtests and strategy metrics

All trading tables have RLS enabled and are restricted to the `service_role`. No API secrets, private keys, seed phrases or exchange credentials are stored in these tables. `venue_accounts.credential_ref` is only a reference to an external secret manager.

## Runtime controls

Three database migrations were applied:
- `institutional_trading_execution_core`
- `market_data_and_agent_orchestration`
- `agent_queue_and_operational_views`

The schema includes atomic task claiming using `FOR UPDATE SKIP LOCKED`, lease expiry, worker heartbeats, lease-owner fencing on task completion, order lifecycle views, strategy PnL views, and open reconciliation discrepancy views.

Ten strategy catalog entries, six agent role profiles, and five discovery hypotheses are registered as disabled/proposed metadata. They are not running engines, validated profitable strategies, or live agents.

## Verified state

The database DDL was first executed in a transaction and rolled back to validate syntax. The worker queue, heartbeat, and task completion functions were exercised inside a transaction and rolled back. The migrations were then applied and the schema inventory was re-read.

At the time of verification, `strategy_runs`, `agents`, `order_intents`, `fills`, and `pnl_ledger` contain zero runtime records. No exchange orders were submitted and no realized trading revenue was generated by this database work.

## Remaining integration work

The deployed `nexus-telemetry-ingest` Edge Function is version 3 and still accepts the original six telemetry kinds only. It has not yet been extended to ingest the new order, fill, risk, balance, position, funding, and reconciliation records. Worker processes are not deployed or running. The Vercel Honeycomb Omega X environment references a different Supabase project ref (`qxfvpcjvoiantjrkorsa`) than the connected active database; that project was not accessible through the current Supabase connection and has not been silently substituted.

The database foundation is additive and does not by itself certify the trading application or any strategy as production-ready.
