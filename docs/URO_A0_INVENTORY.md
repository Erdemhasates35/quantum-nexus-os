# URO A0 — Inventory and truthfulness audit

## Status

Maturity: L2 for exact Git-blob inventory, source classification and static extraction. Semantic truth verification is a separate review task: source prose, comments, identifiers and regex candidates do not prove live runtime behavior.

The reproducible inventory artifact is generated by the URO A0 and A1 Verification workflow. It records the exact checked-out commit for each repository and every tracked Git blob, blob SHA, mode, size, file classification, text/binary classification, line-attributed numeric literals, α references, alpha identifiers, claim candidates, Python AST symbols, cross-language symbol candidates, HTML IDs/classes and CSS selectors.

## Scope and inventory evidence

The inventory was generated from exact Git objects using `git ls-tree -r` and `git cat-file --batch`. Each requested blob SHA is compared with the object ID returned by Git before its content is scanned. This avoids mixing a committed tree SHA with a modified worktree file. Binary and non-UTF-8 blobs remain in the inventory with exact path/SHA/size/mode and are not passed through text parsing.

## Meaning of counts and tags

- Numeric tokens are tagged as source literals. They are not automatically live prices, timings, slots, profits, probabilities or measured KPIs.
- `claim_candidates` are lines selected by lexical heuristics (for example, “production”, “guarantees”, “atomic” or “reproducible”). They are review queues, not assertions that every line is a factual claim.
- Python functions/classes come from Python AST.
- Other language function/type and React component counts are lexical candidates, not compiler/parser-certified symbol tables. Minified, generated, third-party and vendor scopes are kept distinct.
- Ten very long Nexus lines are excluded only from the regex-based cross-language symbol extraction. Git blob inventory and line-based numeric/α extraction still include the full blob bytes.

## α findings

The source-level distinctions are:

- `index.html` logo α: symbolic branding.
- `index.html` footer `α = 0.00729735256`: a physical-reference string; the same footer explicitly says it is not a trading threshold.
- `autonomous-swarm.html` and preserved backups: α and β are symbolic MARL reward weights, not the fine-structure constant.
- `frontend/public/index.html` α-Coupled: legacy architecture branding, not a physical coupling model.
- `QUANTUM_NEXUS_ACADEMIC_ANALYSIS_AND_OPTIMIZATION_REPORT.md`: α-Coupling and α-Efficiency are legacy architecture claims; preserve the document, but do not treat them as active engineering specifications.
- `v16-swarm-execution-contract.md` explicitly rejects the fine-structure constant as an arbitrage threshold or profit predictor.
- `alpha_observations` and alpha telemetry are financial-signal/schema identifiers. They are not the physical constant and must not be renamed based solely on lexical similarity.

The scan’s reference counts are not a count of unique physical-constant use sites: the lexical matcher also finds ordinary alpha terminology. Every candidate carries path, line and context in the JSON artifact for manual classification. The κ implementation is independent of α. No numerical conversion from α to κ is defined.
